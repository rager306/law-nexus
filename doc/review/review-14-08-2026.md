# 2. Ключевое расхождение: TV = новый Work?

| Аспект | de Martim v5 | law-nexus (ADR-0016 §6) |
|---|---|---|
| Каждая правка создаёт | новый F1 Work (Temporal Version) | новую Expression того же Work |
| Обоснование | бразильская Конституция: 100+ EC; каждый EC меняет нормативную личность | РФ: 44-ФЗ = один акт; правки меняют редакцию, не личность |
| Цепочка | TV₁ → TV₂ → … → TVₙ, каждый = Work | Expression₁ → Expression₂ → …, Work один |
| Решение | онтологически точнее для Бразилии | **не копировать**; обосновано юрисдикционной разницей |

Вывод: расхождение не баг, а адаптация к российской юрисдикции. Work стабилен
(ADR-0016 §6, R081). Каждая редакция — Expression. CTV — не F1 Work, а канон
событий membership log.

# 4. Модель: temporal AST с cross-act связями

## 4a. Один акт — пять слоёв одной AST

```text
Work (44-ФЗ «О контрактной системе», стабилен)
 │
 ├─ Expression @ legal_act_effect_day (ред. от 28.12.2025)
 │    ├─ CompositionAst(t) = fold(membership_events ≤ t)
 │    │     Razdel → Glava → Statya → Chast → Punkt → Podpunkt
 │    ├─ EditionAst(t)     = filter(CompositionAst, presence_set этой Expression)
 │    ├─ TextAst(t)        = resolve_CTV(cc, t)          [ЕЩЁ НЕТ — R5-02]
 │    └─ ForceOverlay(t)   снаружи дерева (ADR-0018)
 │
 ├─ Manifestation = EditionOracle (WordML/ODT файл = наблюдение, не канон)
 │
 └─ AmendmentEvent = n-ary причина (кто / что / когда / op / грани)
      ├─ facet: structural  (attach/detach)
      ├─ facet: industrial  (renumber/move/split/merge)
      ├─ facet: text        (CTV wording)         [design-only]
      └─ facet: force       (NormativeEffect)
```

Инварианты:
1. Канон = append-only события. AST = проекция.
2. Один XML ≈ один Expression / Manifestation, не вся история.
3. Маркер «Статья 93» ≠ ComponentConcept без registry.
4. Дерево ≠ сила ≠ применимость ≠ текст CTV.
5. Связь с другим актом — ребро между AST, не слияние деревьев.
6. «ред. от 28.12.2025» и «вступ. в силу с 01.07.2026» — разные часы.
7. Heal = новое событие или waiver. Ластика по дереву нет.

## 4b. Cross-act связи: каждый акт — отдельное AST

| Тип ребра | От → Кому | Семантика | ADR |
|---|---|---|---|
| `amends` | AmendingAct.CC → target CC | причинное микрособытие | 0017/0019 |
| `implements` | decree/order CC → statute CC | конкретизация нормы | 0019 |
| `specifies` | industry act → general norm | отраслевой overlay | 0019/0022 |
| `conflicts_with` | CC ↔ CC | коллизия для resolver | 0019 |
| `cites` | mention → CC | неразрешённая ссылка | 0019/TSG-012 |

## 4c. Пять типов актов и их роли

| Тип | Пример | Роль | AST |
|---|---|---|---|
| ФЗ (закон) | 44-ФЗ, 402-ФЗ | Work, C2 oracle | CompositionAst + EditionAst |
| ПП РФ | ПП № 926, ПП № 145 | C3, `implements`/`specifies` | своё AST, edge к statute |
| Приказ | Минстрой, Минфин | C3, `implements` | своё AST, edge к statute |
| Судебная практика | ФАС, ВС РФ | ADR-0020 overlay | **не** AST; PracticeEvidence |
| ГОСТ / классификатор | ОК 034, ГОСТ Р | смежное законодательство | `cites` edge, чужой Work |
