# Часть A. Букварь для нового агента

Читать сверху вниз. Каждая полка названа, у каждой есть вход / выход /
запрет. Паттерны заземлены ссылкой в Части C.

## A0. Зачем это вообще

**Проблема.** Закон — не один PDF и не папка из 118 XML «ред. от». Это
**стабильная личность** (Work) + **дискретная история ударов** (изменяющие
акты) + **срезы на дату** (что входило в состав, какой был текст, какая сила,
куда отсылали). Если строить историю разницей сводок Консультанта, мы
принимаем фото за дневник и теряем: кто велел, каким речевым актом, с какой
даты, под каким условием, с какими переходными, на какой слот смотрела
отсылка.

**Цель машины.** На запрос «дай 44-ФЗ (или его статью) на дату t» ответить
детерминированным сечением графа: дерево состава + тексты живых слотов +
статус силы + ребра ссылок, каждое с provenance. Не «открой XML ред. от t».
Не «LLM перескажет».

**Не цель этой машины.** Решить, применима ли норма к делу заказчика
(ADR-0023, runtime `[deferred]`). Не конфликт кодексов (ADR-0019 design).
Не практика ФАС как перепись текста (ADR-0020 overlay).

**Почему не Git как store.** Git — **аналогия операций** (commit, checkout,
rm, mv). Закон в Git не кладём. Якорь правки — формула изменяющего акта,
не similarity rename.

## A1. Вселенная объектов (что существует)

Шесть сущностей. Их нельзя схлопнуть.

```text
Work          — закон как личность (номер + дата + орган).
                Пример: федеральный закон от 05.04.2013 № 44-ФЗ.
                Не «редакция 2025».

Слот / CC     — вечное имя куска внутри Work: «статья 31», «пункт 2 ч. 1 ст. 59».
                Человеческий номер — ярлык; личность — путь/wId.
                Repeal слот НЕ удаляет.

CTV           — снимок ТЕКСТА слота между двумя ударами.
                «Изложить ст. 31» закрывает старый CTV и открывает новый.
                Слот тот же.

Событие C1    — один изменяющий закон как СУМКА микрокоманд
                (не один blob «файл поправки»).
                У события глобальный id: на него смотрят и поправка, и слот.

Ребро cites   — факт «слот A в такой-то формулировке отсылает к слоту B».
                Не подстрока «статья 31» и не hyperlink Консультанта.

Сечение / checkout
              — ответ на дату t: какие слоты в составе, какие CTV,
                какая сила, какие рёбра живы. Кэш, не канон.
                Канон = лог событий.
```

**Полки (ленты) одного слота** — читать как независимые колонки одной карточки:

| Полка | Вопрос | Кто пишет | Кто не пишет |
|---|---|---|---|
| личность | что это за кусок навсегда? | mint при первом появлении (WALK-I) | изложение, repeal |
| состав | входит ли в дерево на t? | attach / detach / mv | смена текста |
| текст (CTV) | какая формулировка на t? | изложить / дополнить / исключить слова | repeal (текст храним для цитаты) |
| сила | InForce / Repealed / … на t? | status-событие | «есть в XML ⇒ действует» |
| переходные | для каких старых отношений ещё старый CTV? | оверлей изменяющего акта | возврат слота в дерево |
| ссылки | кто на кого указывает, dynamic/static, interval? | рождение/смерть вместе с CTV **источника** | amends; hyperlink как канон |
| применимость | норма про *это* дело? | **не эта машина** (ADR-0023) | — |

Жёсткие неравенства (уже канон design, `prd/temporal-legal-model.md` §6):

```text
текст есть        ≠  действует
действует         ≠  применимо к делу
опубликовано      ≠  система это видела
сводка «ред. от»  ≠  история закона
mention «ст. 31»  ≠  citation authority
```

## A2. Два времени, которые нельзя сложить

Не «дата документа». Пять ролей часов (ADR-0009); для этой машины минимум:

| Часы | Смысл | Не подменять |
|---|---|---|
| `source_publication` | когда текст издан / выложен | силой |
| `legal_act_effect` | когда удар входит в правопорядок | датой файла XML |
| `system_observation` | когда мы это проглотили | публикацией |
| условие-кнопка | «через 90 дней», «после утверждения порядка» | шестыми часами |
| `factual_event` / `proceeding` | факты и процесс дела | нужны запросу применимости, не fold текста |

Checkout на t читает события с **effect ≤ t** и сработавшей кнопкой.
Событие с effect в будущем **не видно**. Взять latest CTV на вопрос про 2013 =
нарушение каузального конуса.

Интервал жизни CTV **выводится** из событий create/end, не хранится как
истина-поле (`valid_from`/`valid_to` — проекция).

## A3. Конвейер (этапы). Вход → работа → выход → запрет

Это **один** конвейер на весь профиль, не вилка «для 44-ФЗ».

```text
[0] профиль YAML
      ↓
[1] семя (нулевая редакция Work)
      ↓
[2] очередь изменяющих актов (C1), по юридической каузальности
      ↓
[3] разбор пакета → микрокоманды
      ↓
[4] накрутка на ТЕКУЩЕЕ дерево (active + passive + cites)
      ↓
[5] экзамен сводкой (checksum), не parent
      ↓  (повтор 2–5)
[6] машина времени: сечение на t
      ↓
[7] ответ + typed non-success + provenance
```

Применимость, конфликт, практика — **после** шага 7, другими станками.

### Этап 0. Профиль акта

| | |
|---|---|
| **Вход** | YAML: `document_groups`, `mint_levels`, лексика операций, типичные часы, кто имеет право менять |
| **Работа** | параметризовать станок: какие уровни вечные слоты (статья/пункт/…), что такое абзац |
| **Выход** | станок, готовый к любому экземпляру профиля (44-ФЗ — первый) |
| **Запрет** | хардкод «94 статьи», «статья 93 навсегда», «абзац-3-id» |

### Этап 1. Семя

| | |
|---|---|
| **Вход** | текст закона *как приняли* (C0), либо честно earliest oracle с пометкой `from-unknown` |
| **Работа** | mint слотов по `mint_levels`; начальный состав; начальные CTV; сила с даты закона; cites из формул семени (фаза 1–2) |
| **Выход** | дерево слотов + лог «enact» + рёбра cites семени |
| **Запрет** | назвать `edition-0001_rev-initial_from-unknown` юридическим C0 2013 без доказательства |

`from-unknown` в речи оставлять. Past до первого oracle = `Unknown`.

### Этап 2. Очередь C1

| | |
|---|---|
| **Вход** | изменяющие законы (не Δ двух сводок). Пример якорей: 188-ФЗ, 476-ФЗ, 138-ФЗ |
| **Работа** | упорядочить по каузальности (даты эффекта + кнопки), не по дате файла экспорта |
| **Выход** | последовательность пакетов, каждый со своим глобальным event-id |
| **Запрет** | Mode B: «118 редакций Консультанта = 118 commit'ов» |

Сводка «ред. от» — шпаргалка «как слот выглядит сейчас» и экзамен, не commit.

### Этап 3. Разбор пакета (юридическая сумка)

Один ФЗ «о внесении изменений» ≠ одна микрокоманда.

| | |
|---|---|
| **Вход** | текст изменяющего акта (C1) |
| **Работа** | вынуть пачку: слот-цель, речевой акт, часы, условие-кнопка, переходные, цитата новой структуры vs слов |
| **Выход** | список микрокоманд + active-сторона на слотах **поправки** (какая статья 188-ФЗ велела) |
| **Запрет** | склеить «изложить» с «утратил силу» с «приостановить» с «особенности применения»; вывести обязанность из «изложить» |

Речевые акты (не деонтика):

| Акт | Полка | Git-аналогия |
|---|---|---|
| изложить / дополнить / исключить слова | текст | новый blob на том же пути |
| признать утратившим силу | состав + сила | `rm` из дерева; объект в истории |
| приостановить | сила | не `rm` |
| установить особенности / переходные | переходные | оверлей |
| считать пунктом N | личность/состав | `mv` слота (wId едет) |

### Этап 4. Накрутка на текущее дерево

Всегда стоит на результате предыдущего шага (rebase, не патч к 2013 вслепую).

| | |
|---|---|
| **Вход** | текущее дерево + микрокоманды этапа 3 |
| **Работа** | для каждой команды: (a) active в поправке, (b) passive на целевом слоте, (c) закрыть/открыть cites, если ударили по CTV **источника**, (d) каскад детей, если формула про статью целиком |
| **Выход** | новое текущее дерево; лог пополнился |
| **Запрет** | удалить узел слота; завести «статью 31-бис» из-за изложения; переписать чужие cites, потому что изменилась **цель** |

Два независимых точечных процесса на ребре cites:

```text
удар по ИСТОЧНИКУ  → закрыть старое ребро, открыть новое, если фраза жива
удар по ЦЕЛИ       → ребро то же; меняется только checkout цели
```

### Этап 5. Экзамен сводкой

| | |
|---|---|
| **Вход** | сечение графа на дату сводки + файл «ред. от» (Manifestation) |
| **Работа** | checksum состава/маркеров; разъезд = дыра разбора C1, не «затереть деревом фото» |
| **Выход** | pass / fail-closed список расхождений |
| **Запрет** | объявить сводку parent'ом истории; fixture-подшить вырезанные статьи с конца цепочки как будто они всегда были в registry |

HEAD-тест `0080→0081` (статьи 53–59) — **fixture-слой**, не канон WALK-I.
Канон: detach из пакета 476-ФЗ, слоты уже должны быть в графе с семени.

### Этап 6. Машина времени (запрос)

| | |
|---|---|
| **Вход** | Work + дата t (+ опционально: режим «текущая редакция» / «цитата истории» / «дело с переходными») |
| **Работа** | сложить события с effect ≤ t и сработавшей кнопкой; построить сечение всех полок |
| **Выход** | дерево состава + CTV живых слотов + сила + живые cites + provenance |
| **Запрет** | latest; читать события с effect > t; интерполировать две редакции |

### Этап 7. Резолвер ссылок внутри сечения

Три фазы. На HEAD есть только фаза 1 `[bounded]`.

| Фаза | Вход | Выход | Неуспех |
|---|---|---|---|
| 1. Кандидат | текст CTV, hyperlink | `ReferenceMention` / `RawLink` | — (это ещё не слот) |
| 2. Биндинг | mention + Work-контекст | слот-цель (wId) или отказ | `Ambiguous`, `OutOfCorpus`, `HyperlinkOnly` |
| 3. Checkout | ребро + t + режим запроса | CTV+сила цели **или** typed failure | `RepealedTarget`, `DetachedTarget`, `UnknownTarget` |

Mode: **dynamic** (цель = слот, версию берём на t) по умолчанию;
**static** только если текст заморозил («в редакции ФЗ от …»).

`cites` никогда не становится `amends` и не решает конфликт.

### Что получаем в конце (продукт конвейера, не «готово в коде»)

На любую дату t, для любого слота профиля:

1. Входит ли слот в действующее дерево.
2. Какой текст (CTV) и какой список абзацев у родителя.
3. Какая сила, с каким provenance.
4. Какие переходные оверлеи включены запросом дела.
5. Куда отсылал этот текст и кто отсылал сюда (в пределах корпуса).
6. Если чего-то нет — **почему** (coproduct неуспехов), не пустой `None`.

Это **текстово-структурная** правда на дату. Это ещё не «какая норма
выигрывает спор» и не «обязан ли заказчик».

## A4. Иерархия и абзац (чтобы не сломать ссылку)

Нумерованные уровни (глава / статья / часть / пункт / подпункт — как скажет
`mint_levels`) = **вечный слот**.

Абзац без номера = **элемент списка внутри родителя на дату операции**.
Вставка/исключение сдвигает хвост. Позиционный id из XML сводки после сдвига
лжёт.

Перенумерация («считать пунктом 5» / art.2 стал art.15):

```text
wId / слот  — тот же (ортолог)
eId / номер — новый ярлык
новый «пункт 2», появившийся на месте старого — ДРУГОЙ слот (паралог)
```

Ссылка dynamic на старый «пункт 2» должна попасть в **уехавший** wId,
не в тёзку.

Каскад: «статью 59 признать утратившей силу» вынимает детей из **состава**.
Их личности живы. Ссылка на статью ≠ ссылка на все части, пока формула
не охватывает их юридически.

## B1. Изложить ст. 31 — дух 188-ФЗ, effect 02.07.2013

**Вход:** пакет 188-ФЗ + текущее дерево B0.  
**Микрокоманда:** `replace_text(slot=31, new=T31₁, effect=2013-07-02)`.  
**Событие:** `E-188-art31` (глобальный id).  
Active: статья 188-ФЗ, которая велела. Passive: слот 31.

Что **не** делаем: не убиваем слот 31; не трогаем текст 93; не закрываем
CITE-93-31 (источник T93₀ жив); не открываем «31-бис».

| Слот | Состав | Текст | Сила | Ссылки |
|---|---|---|---|---|
| 31 | да | **T31₁** (T31₀ закрыт событием) | InForce | входящая от 93 |
| 59 | да | T59₀ | InForce | входящая от 93 |
| 93 | да | T93₀ | InForce | те же два ребра |

Клей:

```text
CITE-93-31 смотрит в СЛОТ 31, не в файл текста.
checkout 31 @ 2013-07-01 → T31₀
checkout 31 @ 2013-07-03 → T31₁
ребро одно и то же
```

**Выход:** новое дерево. Сводка «ред. от 02.07.2013» — экзамен маркеров ст. 31.

## B2. Исключить абзац первый п. 2 ст. 59 — учебный, effect 01.09.2014

**Микрокоманда:** вынуть элемент № 1 списка родителя `59/ч.1/п.2` на дату операции.

До `[A, B]`, после `[B]`. Слот п.2 вечен. A живёт в истории операции, не в списке.

Ссылки 93 не затронуты (93 не ссылалась на абзац).

Зачем шаг: показать eId≠wId. «Абзац первый» 31.08.2014 = A; 02.09.2014 = B.
Позиционный id сводки после сдвига попал бы не туда.

## B3. Статью 59 признать утратившей силу — дух 476-ФЗ, effect 01.01.2022

**Вход:** пакет 476-ФЗ + дерево после B2.  
**Микрокоманды:**

1. detach слота 59 и каскад детей с 2022-01-01;
2. сила `Repealed`, provenance = 476-ФЗ;
3. переходные: «для извещений до 01.01.2022 применяй последний CTV 59».

**Событие:** `E-476-art59`. Typing ближе к концу существования состава/силы,
не к новому изложению. Текст последнего CTV **храним**.

476-ФЗ не обязан излагать ст. 93. T93₀ жив → CITE-93-59 **живо**.

Сечение **02.01.2022**, режим «текущая редакция»:

| Слот | Состав | Сила | Текст | Cites |
|---|---|---|---|---|
| 31 | да | InForce | T31₁ | входящая от 93 → успех |
| 59 | **нет** | **Repealed** | последний CTV в истории | CITE-93-59 живо; checkout цели = RepealedTarget + текст для цитаты |
| 93 | да | InForce | T93₀ | →31; →59 (ребро не удалено) |

Сечение **30.12.2021**: 59 ещё в составе, InForce.

Запрос «закупка декабря 2021, спор в 2023»:

```text
сечение 2023  PLUS  переходная полка 476-ФЗ
≠ «открой 44-ФЗ на 2023»
для этого отношения 59 читается как старый CTV
```

Два режима (развилка F11-C, Review 11): действующая норма → `RepealedTarget`;
цитата истории / переходные → успех с пометкой Repealed.

## B4. Сводная машина времени

```text
2013-04-05  семя: 31,59,93; CITE 93→31 и 93→59
```
