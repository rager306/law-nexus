# 1. Идея (three orthogonal mechanisms)

| Механизм | Что решает |
|---|---|
| A. Document groups (YAML-словарь типов актов) | у каждого типа своя лестница уровней, свой атом |
| B. Гранулярность как параметр профиля | где CC/text-атом, а где контейнер — данные, не код |
| C. Рекурсивная лестница (аналог рекурсии/RLM) | самоподобная вложенность п. 4 → 4.1 → 4.1.2 без перечисления уровней |

## 1a. Двухслойная модель уровней

- **Слой 1 — роли (закрытое ядро):** `container` / `unit` / `subunit` /
  `text-only`. Роли остаются закрытым словарём → KBO-R028-дисциплина и
  forbidden-kinds не ослабевают.
- **Слой 2 — токены уровней (открытые, per-группа):** префиксы, стили
  нумерации, алиасы. Токен валиден только внутри объявившей группы; вне —
  `Unknown` (fail-closed). Обобщает существующие
  `decode_marker_prefixes`/`decode_numbered_markers` из глобальных в
  групповые секции.

## 1b. Форма профиля (схема, не реализация)

```yaml
document_groups:
  - group: federal_law
    detect: {path_needles: "law_|federalnyi-zakon"}
    ladder:
      - {token: glava,   role: container}
      - {token: paragraph, role: container}
      - {token: statya,  role: unit}
      - {token: chast,   role: subunit}
      - {token: punkt,   role: subunit, recursive: true, max_depth: 2, compound: true}
      - {token: podpunkt, role: subunit}
    granularity: statya
    text_boundary: [unit, container]
```

## 1c. Место в онтологии: переносить привязки, не словарь

- Словарь остаётся в YAML-каталоге (мета-промпт-слой). В граф уходит только
  факт-привязка: `Work ──(parsed_as)──▶ DocumentGroupRef{group, catalog_version}`
  (хеш секции каталога — философия EditionOracle: проверяемость на дрейф).
- Привязка — на **Work** (тип акта — свойство Work, не Expression/Manifestation).
- Новые `node_kind: DocumentGroupRef` + `edge_kind: parsed_as` в
  `kb-ontology.yaml`; non-claims обязательны: привязка — эвристика класса
  `system_observation`, не юридическая классификация; запрет `ProfileAsClock`,
  запрет повышения force/applicable (расширение forbidden-словарей и guards).
- Нейминг: «структурный профиль»/`document_groups` ≠ ADR-0022 industry
  profiles ≠ ADR-0027 classification profiles — три понятия, глоссарная запись
  §3 обязательна до именования типов (правило temporal-legal-model §3).

## 1d. Рекурсивная гранулярность (аналог рекурсии/RLM)

- **Ранг становится парой `(порядок_роли, глубина)`** — лексикографически;
  механика стека `pop while top_rank >= rank` обобщается без изменения.
- **CC-path идентичность:** `cc:44-fz:statya-93/punkt-4/punkt-4.2` —
  рекурсивные идентификаторы; реестровые биндинги генерируются лестницей путей
  (генератор `registry_bindings_generator.rs` уже существует); ссылочный канал
  «п. 4 ч. 3 ст. 93» в будущем — path-lookup (TQ-05); попутно чинит дефект
  `changed_article_texts` (ключ по голому `number`).
- **Глубина — политика, не синтаксис:** `max_depth` per уровень per группа;
  превышение или не-каталожный токен → карантин → census.
- **RLM-петля двухконтурная:** ONLINE — детерминированный walk по YAML-данным
  (рекурсия без недетерминизма); OFFLINE — самоуточнение профиля по
  накопленным наблюдениям: новый класс census `StructuralNearMiss` →
  `rank_unknown_forms` → `render_yaml_patch_candidates` → человек применяет
  через существующий `apply_patch_candidates` API (D185: никогда авто-apply).
  Роль LLM/агента — только OFFLINE-предложения, что соответствует ADR-0027
  («агент может NLP offline; парсер применяет YAML online»).

# 2. Разведка применимости (corpus reconnaissance)

Метод: агрегатная пред-декодная разведка по `consru_export`
(gitignored, local `[smoke]`). Метаданные — `documents.csv` (31 336 документов)
и манифесты слоёв; структурная статистика — регулярки по `<w:p>/<w:t>` на
равномерной выборке ≤40–60 файлов на группу (детерминированная). Только
счётчики; сырой юридический текст не сохраняется. Это **не parser evidence и
не качество декодера** — разведка формы.

# 4. Что подкрутить (tuning list, приоритет)

1. **Двухфакторная детекция группы** (R8-07): метаданные каталога + структурный
   зонд; при конфликте — fail-closed `Unknown` (не угадывать).
2. **Потолки рекурсии из данных** (R8-03): `max_depth`: law.punkt=2,
   order.punkt=4 (эскалация 6 — через census), resolution.ch=3; превышение →
   StructuralNearMiss, не эвристика.
3. **Групповые стили нумерации** (R8-04): суффикс/скобка/буквы — секции группы;
   FAS-гейтинг (R8-05) как явный тест-кейс.
4. **Пленум** (R8-06): решение о non-authoritative punkt-индексе без CC.
5. **Токены примечание/приложение** (R8-09): роли subunit-text/container.
6. **Кодексы как отдельная группа** (R8-08).
7. **Реестр биндингов как производная**: генератор лестницей путей; объём
   (921 акт × сотни пунктов) — реестр перестаёт быть курируемым списком,
   становится артефакт-проекцией с human-гейтом на диффе.
8. **Governor coverage-правило**: из «Rust enum ⊆ YAML» обобщить на «лестница
   группы ⊆ каталог токенов; роли закрыты; группа ссылается на версию каталога».
9. **Глоссарий §3 до типов**: document group / structural profile / CC-path.
10. **Golden-регрессия federal_law@v1** до любых изменений (R8-14).
