# Review 10 — Итерация модели: изменяющий акт как commit, юридическая семантика, машина времени

Дата: 20–21.08.2026. Опора на HEAD `336be5de3a908e7d3e9580224695b48a5609539c`
и на чат-итерацию после Review 9 (`doc/review/review-20-08-2026.md`).

Это **иммутабельный L0-источник** (ADR-0024): фиксация **одной итерации**
улучшения модели нормативного акта. Текст **не утверждён** как канон, не
закрывает TSG, не повышает lifecycle ADR, не чеканит Rust-типы, не двигает
`fsm.current` / O3 / TSG-017 S4 и не является пакетом Review Case.

Связь с Review 9: WALK-S (иерархия снимка) и WALK-I (выращивание CC) остаются.
Эта итерация **переориентирует источник истории (WALK-T)**: канон накрутки —
цепочка **изменяющих актов** на нулевую редакцию, а не Δ сводок «ред. от».
Сводка Консультанта/Гаранта — опора для разбора поправки и экзамен checksum,
не commit.

Инжект M001 (FalkorDB / GraphBLAS / «WordML нельзя, пока не доказан 44-fz.odt»)
к этой модели **не применяется**. Живой канон сравнения: ADR-0009, 0016–0023,
D046 (ядро проекта владеет смыслом; LRMoo/ELI/AKN/LKIF — compatibility).

Объекты сравнения:

- de Martim v5, arXiv:2506.07853v5 (уже разобран в Review 5/6);
- европейские / международные линейки идентификации и обмена: ELI, Akoma Ntoso
  (AKN), LRMoo/FRBR, LKIF, CEN MetaLex / LegalRuleML — **как стандарты

# 1. Идея итерации (простым языком)

**Нормативный акт — один Work** (для 44-ФЗ: федеральный закон от 05.04.2013
№ 44-ФЗ). Это не папка из 118 XML.

**Нулевая редакция** — закон *как приняли* (семя). Файл экспорта
`edition-0001_rev-initial_from-unknown` **нельзя молча назвать семенем**:
токен `from-unknown` = покрытие в прошлое Unknown, пока C0 не опознан.

**История** пишется не разницей сводок, а каждым **изменяющим актом**:
прочитать юридический пакет (кого трогает, характер операции, часы вступления,
отлагательные условия, переходные) и **накрутить микрособытия на семя**, уже
после предыдущих поправок (как rebase, не как патч к тексту 2013 вслепую).

**Машина времени:** «дай редакцию на дату t» = checkout из графа
(семя + микрособытия с эффектом ≤ t и сработавшим условием), а не «открой XML
ред. от t». Сводка на близкую дату — **сверка**, не ответ.

**Иерархия как git-дерево слотов**, не как один blob-файл:

- нумерованные уровни (глава, статья, часть, пункт, подпункт) — **вечный слот**
  (путь); «изложить» = тот же путь, новый текст; «утратил силу» = вынуть из
  состава, слот в истории остаётся;
- **абзац** чаще без номера — не вечный файл, а элемент **списка внутри
  родителя** на момент операции (вставка сдвигает хвост);
- перенумерация («считать пунктом 5») = перенос слота, история едет со слотом.

**Юридическая семантика** (над git-операциями, не вместо них):

- изложить / дополнить / исключить слова ≠ признать утратившим силу ≠
  приостановить ≠ «установить особенности применения»;
- текст/состав, сила, переходные, применимость к делу — **четыре полки**;
- один изменяющий ФЗ — **сумка** микрособытий с разными датами и кнопками
  («через 90 дней», «со дня опубликования», «после утверждения порядка»).

**Не хардкод 44-ФЗ:** те же станки; профиль (`document_groups`) задаёт семя,
кто имеет право менять, глубину вечных слотов, лексику операций, типичные часы.

Примеры-якоря корпуса (не константы алгоритма): 188-ФЗ (02.07.2013);
476-ФЗ и вырезание «бумажных» статей 53–59… с 01.01.2022; 138-ФЗ → ст. 31/43;
333-ФЗ → ст. 95.

# 3. Сравнение с de Martim v5

de Martim: event-centric CTV/CLV, validity из событий, n-ary F27∩E64,
макро→микро (P9), сильная реконструкция текста компонента. Law-nexus уже взял
event-sourcing и **отверг** TV = новый F1 Work (РФ: правки меняют редакцию,
не личность акта).

| Ось | de Martim v5 | Эта итерация | Вердикт |
|---|---|---|---|
| Стабильный акт | Concept = F1 Work | Work = номер+дата+authority | паритет; TV=новый Work **не брать** |
| Версия на дату | TV = новый Work | Expression + fold(events ≤ t) | оставить law-nexus |
| Компонент | CW / CTV / CLV | CC + слот-путь + text log | паритет идеи; абзац-список — **наше** уточнение (статья слабее на ненумерованном уровне) |
| Событие правки | одно n-ary на правку | n-ary **плюс** сумка микрособытий с разными часами/условиями внутри одного C1 | взять P9; **добавить** мульти-clock bag (типично для РФ ФЗ «о внесении») |
| Откуда события | предполагается чистый корпус поправок | **обязательный** разбор C1; сводка не замена | усиление относительно Mode B Review 9; ближе к духу статьи, чем Δ XML |
| Validity | [t_start, t_end) из create/end событий | то же + отлагательные кнопки + vacatio | паритет + явные условия |
| Текст на t | P190 / resolve_CTV сильный | `resolve_ctv` + список абзацев родителя | цель та же; абзацный сдвиг статья почти не моделирует |
| Иерархия | R67 has part | git-дерево слотов + `mv` при перенумерации | паритет; операция «считать пунктом N» у нас first-class |
| Applicability | в valid time смешана / не наша полка | явно **запрещена** в этой машине (ADR-0023) | law-nexus строже — оставить |
| Корпус | Конституция Бразилии, 100+ поправок | 44-ФЗ как первый экземпляр профиля | не копировать юрисдикцию; копировать метод «поправка = событие» |

**Взять у de Martim:** событие как узел; validity из событий; макро C1 → микро
на CC; не XML-DOM как канон.

**Не взять:** новый Work на каждую правку; OWL как runtime; applicability как
свойство valid time; игнор ненумерованных абзацев как «просто текст CTV»
без правил сдвига.

**Где мы уже шире:** пять часов, сила ≠ текст, переходные, профили актов,
fail-closed evidence class (legislative > hypothesized > hint).

**Где статья сильнее:** исполняемая реконструкция текста до абзаца на всём
корпусе поправок; формальная LRMoo-запись.

# 4. Сравнение с европейскими / международными стандартами

D046: они **не заменяют** ядро. Ниже — зачем каждый стандарт и где итерация
с ним расходится.

## 4a. ELI (European Legislation Identifier)

ELI даёт **URI акта/фрагмента** (`eli/…/article/93/…`) и метаданные версии.
Это **адрес**, не дневник правок.

| ELI | Итерация | Вердикт |
|---|---|---|
| стабильный идентификатор фрагмента | слот-путь / CC-path | совместимо как проекция `to_eli_uri` (уже ADR-0016 R5-07) |
| версия документа | Expression / checkout на t | ELI не несёт сумку часов одного C1 |
| нет обязательной модели «изложить vs утратил силу» | речевой акт поправки | ELI **недостаточен** как канон истории |
| нет абзацного списка | список в родителе | ELI не решает сдвиг абзацев |

Не строить машину времени «как ELI URI на дату». URI — этикетка слота.

## 4b. Akoma Ntoso (AKN)

AKN — **XML-схема документа**: иерархия, eId, версии как документы, иногда
eventRefs. Силён как Manifestation/обмен.

| AKN | Итерация | Вердикт |
|---|---|---|
| дерево глав/статей/пунктов | WALK-S + слоты | паритет формы |
| eId привязан к разметке документа | слот живёт **между** документами | AKN-eId ломается, когда абзац сдвинули, а id был позиционным |
| версия = документ | версия = fold событий | не копировать «документ = истина редакции» |
| eventRef опционален | C1 **обязан** быть каноном | взять дух ссылки на событие, не схему XML как store |

Сводка Консультанта ближе к AKN-документу, чем к git-истории. Путать их —
старая ошибка Mode B.

## 4c. LRMoo / FRBR (WEMI)

Уже каркас L1: Work / Expression / Manifestation / Item.

| LRMoo | Итерация | Вердикт |
|---|---|---|
| F1 Work | стабильный 44-ФЗ | паритет; не TV=Work |
| F2 Expression | датированная редакция = **проекция** checkout | Expression не заводит сама события |
| F3 Manifestation | XML/ODT сводка или официальный PDF | checksum, не parent |
| F27/E64 события | AmendmentEvent + микропакет | паритет с de Martim; сумка часов — расширение |

## 4d. LKIF / LegalRuleML

LKIF и LegalRuleML описывают **нормы как правила** (деонтика, исключения).
Это ближе к будущему NormRule / ADR-0023, не к машине времени текста.

| LKIF / LegalRuleML | Итерация | Вердикт |
|---|---|---|
| обязан / вправе / запрет | **не** в этой волне | не выводить из лексики «изложить» |
| defeasible rules | переходные / особенности — оверлеи | можно позже проецировать; не канон L2 |
| нет git-дерева абзацев | якоря слотов | стандарт **не заменяет** иерархическую машину времени |

Смешать «пункт 4 изложить» с «это обязанность заказчика» — снова склеить
полки. Итерация это запрещает.

## 4e. CEN MetaLex

MetaLex — обмен законодательными XML, именование версий и ссылок.
Как ELI/AKN: **документный** слой.

Взять: стабильные имена фрагментов, явные версии.  
Не взять: версия документа как замена event log; молчаливый позиционный id абзаца.
