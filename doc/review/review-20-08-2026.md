# 0. Не путать три «рекурсии»

В Review 8 «рекурсия» означала **вложенность маркеров** (п. 4 → 4.1 → 4.1.2).
Для Temporal AST этого мало. Есть **три ортогональных обхода**. Смешивать их
— тот же класс ошибки, что схлопнуть три канона L2 в `NormativeBlob`.

| Обход | По чему | Что возвращает | Что это не есть |
|---|---|---|---|
| **WALK-T** (время) | упорядоченная цепочка Manifestation/Expression одного Work | append-only события + `AST(t_k) = fold(log, t_k)` | DOM очередного XML |
| **WALK-S** (структура) | маркеры одного снимка, ранг `(порядок_роли, глубина)` | дерево membership-drafts + тела единиц | юридическая сила, Applicable |
| **WALK-I** (identity) | первое появление ключа маркера в жизни Work | стабильный CC; повтор = тот же CC | номер статьи сам по себе |

44-ФЗ — экземпляр: Work `federal:zakon:2013-04-05;44-fz`, группа
`federal_law@v1`, цепочка `edition-0001 … edition-0118` в `consru_export`.
Алгоритм ниже не содержит «94 статьи», «8 глав», «статья 93» как констант.

# Часть B — Рекурсивная модель Temporal AST

## B1. Что строим

Не DOM. Не «текущая редакция Консультанта». Не одно дерево законодательства РФ.

```text
Work W                          # стабилен (ADR-0016 §6)
  └─ Expression E_k @ clock     # датированная редакция; не новый Work
        Manifestation M_k       # XML/ODT файл = EditionOracle (checksum)
        CompositionAst(t)       # fold(membership ≤ t)
        EditionAst(t)           # filter(presence этой Expression)
        TextAst(t)              # resolve_CTV(cc, t) на mint-уровне группы
        ForceOverlay(t)         # снаружи дерева (эта волна не строит)

AmendmentEvent                  # n-ary причина (кто/что/когда/op/грани)
  facets: structural | industrial | text | force
  evidence_class: legislative > hypothesized_from_oracle_diff > editorial_hint
```

Инварианты (Review 4 §4, ADR-0017):

1. Канон = append-only события. AST = проекция `fold(events ≤ t)`.
2. Один файл ≈ один Expression/Manifestation, не вся история.
3. Маркер «Статья 93» ≠ CC без identity-правила (WALK-I).
4. Дерево ≠ сила ≠ применимость ≠ текст.
5. Связь с другим актом — ребро между AST, не слияние деревьев.
6. «ред. от» и «вступ. в силу с» — разные часы.
7. Heal = новое событие или waiver. Ластика нет.

## B2. Параметры алгоритма (почему это не хардкод 44-ФЗ)

Вход — **конфигурация экземпляра**, не ветки `if act == "44-FZ"`.

| Параметр | Откуда | Экземпляр 44-ФЗ (сейчас) |
|---|---|---|
| `WorkId` | number + enactment_date + authority (ADR-0016) | `federal:zakon:2013-04-05;44-fz` |
| `document_group` | двухфакторная детекция YAML (R8-07) | `federal_law@v1` |
| `ladder` + `roles` + `max_depth` | `document_groups.groups[]` | glava→…→punkt recursive 2 |
| `granularity` / `text_boundary` | то же | mint = `statya`; boundary = unit+container |
| `mint_levels` | подмножество ladder, **данные профиля** | первая волна `{glava, statya}` — **не** запрет на punkt-CC навсегда; D192 — текущий потолок registry, не закон природы |
| `chain` | каталог изданий Work, сортировка ниже | `edition-0001 … edition-0118` |
| `clock_extract` | filename / catalog / XML, с классом доказательства | process truth, пока не legal calendar |
| `bindings_policy` | WALK-I, не снимок последней редакции | **выращивается**; YAML 0118 — только bootstrap/check |
| `evidence_policy` | C1, если идентифицирован, иначе oracle-diff | hybrid: C2-цепочка + C1 overlay (138/333/484 на диске) |

Другой акт (402-ФЗ, кодекс, ПП) подставляет другие значения тех же ручек.
ПП уже доказывает: `granularity: punkt` меняет mint-уровень без второго
коллектора «для постановлений» (KBO-R067 слой 2).

## B3. Честность «редакции 0»

В экспорте earliest файл 44-ФЗ:

```text
edition-0001_rev-initial_from-unknown_19d3c051.xml
```

| Утверждение | Верно? |
|---|---|
| Это earliest **oracle** в локальном consru_export | да, как имя и как seed тестов 0001→0002 |
| Это юридический C0 «текст на 05.04.2013» | **нет** — токен `from-unknown` и Review 4: Coverage в прошлое = Unknown |
| Это основание mint'ить CC «как в 0118» | **нет** — 0118 не содержит статей, живших в 0001 и снятых 476-ФЗ |
| Это Mode A legislative replay | **нет** — Mode B (oracle-anchored), пока C1 не привязан к Δ |

**Правило seed:** `E[0] := earliest Manifestation in chain`. Класс событий
seed = `hypothesized_from_oracle_diff`, пока нет C0/C1. Не называть seed
«оригинальной редакцией закона» в lifecycle-утверждениях.

Режимы сборки (Review 4 §5) — параметр, не код акта:

| Режим | Когда | Канон событий | Потолок |
|---|---|---|---|
| A. Legislative replay | C0 + ряд C1 | `legislative` | золотой |
| B. Oracle-anchored | цепочка сводок | `hypothesized_from_oracle_diff` | рабочий, честный |
| A+B hybrid | часть C1 + несколько C2 | C1 побеждает; C2 — checksum | целевой для 44-ФЗ |

Обзор (`C2hint`) **никогда** не повышает класс до `legislative`.

## B4. Сортировка цепочки (WALK-T порядок)

`chain` — не «порядок файлов в ls» как юридическое время.

```text
sort key:
  1. provider_ordinal          # edition-0001 < edition-0002 < … < edition-0118
  2. legal_act_effect_day      # если известен; иначе Unknown, не выдумывать
  3. source_publication_day    # независимо (ADR-0009)
запрещено:
  - сортировать по mtime
  - считать «ред. от» = «в силе с»
  - вставлять обзор в chain Work
```

Два файла с одним ordinal и разными `from-*` / `rev-*` — разные
Manifestation одного или соседних Expression: разводить по
`legal_act_effect` vs publication, не схлопывать. Пример уже в корпусе:
`edition-0080_rev-2021-12-30_from-unknown` и
`edition-0081_rev-2021-12-30_from-2022-01-01` — одна календарная «rev»,
разный `from` (вступление в силу 476-ФЗ).

## B5. WALK-I — выращивание CC (анти-хардкод)

Сегодняшний `kb-hierarchy-registry.yaml` для `law_2013-04-05_44-fz` —
**снимок 0118** (8 glava + 94 statya). Исторический слой 0080→0081
подмешивает снятые статьи **локально в тесте**. Это анти-паттерн канона.

Канон identity:

```text
key(marker) := (WorkId, path_tokens, level, number)
  path_tokens — CC-path синтаксис D191:
    cc:{work}:{token}-{n}[/ {token}-{n}…]

первое появление key в chain[0..k]  → mint CC (стабильный id)
повтор key                          → тот же CC
key исчез (detach), потом тот же number на другом path
                                    → новый CC или Conflict; молчаливый reuse запрещён
unmapped / non-catalog token        → Unknown; quarantine; census
number+level без path и без mint_levels
                                    → не CC (KBO-R024)
```

`mint_levels` читается из профиля:

- `federal_law@v1` волна-1: mint `{glava, statya}`; chast/punkt/podpunkt
  участвуют в WALK-S как **subunit** (текст в теле единицы, KBO-R067 слой 3);
- та же процедура с `mint_levels ⊇ {punkt}` даёт nested CC-path, когда
  human-гейт снимет D192 — **без нового алгоритма**;
- `government_resolution`: mint `{punkt}` уже сейчас.

Реестр YAML становится **проекцией** выращенной карты + human-gate на диффе
(Review 8 §4.7), не курируемым списком «все статьи 44-ФЗ».

## B6. WALK-S — структурный обход одного снимка

Уже исполняется идея Review 8 / `propose_membership_from_markers`:

```text
rank(marker) = (role_order(group.ladder), depth)
stack = []
for marker in document_order:
    if marker.level ∉ group.ladder:          # в т.ч. РАЗДЕЛ в ФЗ (R8-08)
        Unknown → quarantine → census; skip stack
    if depth > max_depth(level, group):
        StructuralNearMiss → quarantine; не эвристика
    while stack.top.rank >= rank(marker):
        pop
    if marker.level ∈ mint_levels and Bound:
        attach(parent=stack.top, child=CC(marker))   # draft, не commit
        push
    else:
        # subunit / subunit-text: не mint, но накапливает тело единицы
        accumulate_into(current_unit, marker)
```

Это **тот же** стек, что для ПП и приказов. Меняется таблица ролей и
`mint_levels`, не процедура. Рекурсия здесь — самоподобная вложенность
токена с `recursive: true`, не обход графа актов.

Тело единицы (`text_boundary`): маркерная строка не входит в текст;
накопление до следующего unit/container; ProviderComment не входит
(KBO-R060). Для 44-ФЗ волна-1 единица = statya; вложенный пункт — строки
тела, не отдельный TextVersionEvent.

## B7. WALK-T — временной обход цепочки (главная рекурсия этой модели)

Итеративная форма (рекурсия по k; хвост — fold, не XML).

```text
log_membership, log_presence, log_text := empty
identity := empty map                 # WALK-I
AST := {}                             # k → EditionAst

# --- seed ---
M0 := chain[0]
G  := detect_group(M0)                # fail-closed Unknown/Conflict
assert G is Bound                     # иначе STOP, не угадывать ФЗ
markers0, units0 := decode_extract_walkS(M0, G)
identity := grow(identity, markers0)  # mint first-seen
bind0 := bind(markers0, identity)
drafts0 := propose_admit(bind0)
commit membership attach for drafts0 @ t0
       presence include for bound CCs @ t0
       text events for each unit @ t0
       evidence_class := hypothesized   # пока нет C0
AST[0] := edition_ast_at(log, t0)
verify: fold Δ snapshot(M0) == 0 or heal(new event | waiver)

# --- step ---
for k in 1..N:
    Mk := chain[k]
    markers_k, units_k := decode_extract_walkS(Mk, G)
    identity := grow(identity, markers_k)          # новые статьи = новые CC
    Δ_struct := diff_marker_sets(bound(k-1), bound(k))
    Δ_text   := changed_unit_texts(units_{k-1}, units_k, granularity(G))

    events := []
    if C1_covers(Δ, k):                            # hybrid
        events += micro_events from C1             # class=legislative
        # C2 остаётся checksum, не parent
    else:
        events += drafts_from_marker_diff(Δ_struct)  # facet=structural
        events += drafts_from_text_diff(Δ_text)      # facet=text
        class := hypothesized_from_oracle_diff

    append events @ t_k onto the three logs        # never edit past
    AST[k] := edition_ast_at(log, t_k)
    drift := AST[k] Δ snapshot(Mk)
    if drift ≠ 0: heal by NEW event or explicit waiver
    # industrial ops (renumber/move/split/merge):
    #   только если Δ нельзя свести к attach/detach+text;
    #   plan_industrial_op fail-closed; не угадывать «это перенумерация»

return (log, identity, AST, coverage, unknown, conflict)
```

**Рекурсивная формулировка** (эквивалент):

```text
build(chain):
    if chain is [M0]:   seed as above; return state0
    state := build(chain[0..k-1])
    return step(state, chain[k])
```

Канон хранится в `log`, не в `AST[k]`. `AST[k]` можно выбросить и
пересчитать. Поэтому **кэш fold — оптимизация, не канон**. Для 118 шагов
без durable log повторный decode всех XML будет дорогим — это аргумент
для **журнала событий** как артефакта прогона, не для записи oracle-дерева.

## B8. Три канона на каждом k (не схлопывать)

| Канон | События шага | Проекция | 44-ФЗ волна-1 |
|---|---|---|---|
| Membership | attach/detach (и industrial, если доказан) | `fold_membership_at` | главы и статьи; subunit без CC |
| Presence | include/exclude per Expression | `fold_expression_presence` | не наследовать молча в следующий E |
| Text | TextVersionEvent на mint-уровне | `resolve_ctv(cc, t)` | тело statya; punkt внутри тела |

`edition_ast_at(t)` = membership fold ⊕ presence filter; text резолвится
по CC отдельно. Force — не поле узла.

Целостность шага:

```text
∀ cc ∈ mint(G):
    resolve_ctv(cc, t_k) ∈ {Resolved, Unknown, Conflict, MissingAnchor}
compilation(t_k) fail-closed, если выбран режим whole-act
    и любой mint-CC не Resolved          # ADR-0017 §4
волна-1 44-ФЗ: whole-act compilation НЕ включаем
    (иначе 118 шагов умрут на первых Unknown вложенных единиц)
```

Это честный потолок: **лес единиц**, не «полный текст закона как один CTV».
