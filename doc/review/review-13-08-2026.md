Статья отвечает на «какой был **текст** нормы на дату». Мы шире (5 часов,
force ≠ text ≠ applicable) и тоньше на реконструкции текста.

| Иерархия | CC R67 + Expression R5 | membership fold + presence | паритет идеи |

# 4. Модель: что такое temporal AST

Не DOM WordML. Не одно дерево «законодательство РФ».

```text
Work (стабильный концепт, напр. 44-ФЗ)
  └─ Expression @ legal_act_effect_day
        ├─ CompositionAst(t)  = fold(membership ≤ t)
        ├─ EditionAst(t)      = filter(presence этой Expression)
        ├─ TextAst(t)         = resolve_CTV(cc)     [ещё нет]
        └─ ForceOverlay(t)    снаружи дерева

EditionOracle(файл) = наблюдение Composition+Text на дату title
                    ≠ Expression (файл = Manifestation)
AmendmentEvent      = n-ary причина (кто / что / когда / op / грани)
AST@t               = fold(events ≤ t)
drift(t)            = AST@t Δ Oracle@t
```

Инварианты:

1. Канон = append-only события. AST = проекция.
2. Один XML ≈ один Expression / Manifestation, не вся история.
3. Маркер `Статья 93` ≠ ComponentConcept без registry.
4. Дерево ≠ сила ≠ применимость ≠ текст CTV.
5. Связь с другим актом — ребро между AST, не слияние деревьев.
6. «ред. от 28.12.2025» и «вступ. в силу с 01.07.2026» — разные часы.
7. Heal = новое событие или waiver. Ластика по дереву нет.

# 6. Сборочный pipeline (идея, не код)

Отдельный FSM от KB-readiness (`O2_calendar_ordinal`). Состояния:

```text
S_ingest → S_decode → S_extract → S_identify
  → S_bind → S_propose → S_admit
  → S_commit → S_fold → S_verify
  → S_heal | S_ready_bounded
```

P0–P3 уже исполняются (WordML → блоки → маркеры / mentions / phrases).
Дыра: маркеры идут **списком**, не стеком; attach ещё не предлагается.
Пять слоёв одной AST: identity / composition / edition / bind / force overlay.
Межрёбра: `amends` / `implements` / `specifies` / `conflicts_with` / `cites`.

Контрольная редакция — checksum: `fold(log, t) ≈ snapshot(ред. от t)`.
Она никогда не записывается как parent следующей.
