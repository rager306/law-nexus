# Часть A. Общая идея (с нуля, коротко)

## A.1 Проблема

Российский нормативный акт живёт как: стабильная личность + дискретные
юридические события изменения + срезы на дату. Провайдеры (Consultant,
Garant) публикуют **сводные редакции** — фотография результата, не дневник.
Diff двух фотографий показывает «что изменилось», но не устанавливает: кто
велел, какой формулой, с какой даты, под каким условием, с какими
переходными, изложить или отменить.

Хранить историю как цепочку XML-сводок = принять фото за причину. Отсюда
все типовые ошибки юридических RAG: «есть в файле ⇒ действует», «последняя
редакция ⇒ правильная цель ссылки», «изложили ⇒ уже в силе».

## A.2 Формула

```text
официальные доказательства (Evidence Vault)
+ append-only bitemporal ledger доказательных утверждений о юридических событиях
+ типизированная алгебра поправок (Instrument → Provision → MicroOperation → Effect)
+ deterministic amendment compiler
= проекции:
    persistent lossless CST (green) + semantic legal AST (red)
    temporal structure / reference graph
+ deterministic checkout(legal_as_of, known_as_of, view_mode)
```

Три ключевых «не»:

1. **Snapshot ≠ commit.** Сводка — oracle/checksum (ADR-0017 §1c), экзамен,
   не источник истории.
2. **Извлечённое событие ≠ юридический факт.** Канон — ledger **утверждений**
   с evidence span, статусом (Proposed/Validated/AuthoritativeInternal/
   Rejected/Superseded) и recorded_at. Поздняя коррекция не переписывает
   прошлое знание системы.
3. **Проекция ≠ истина.** CST/AST/граф/срез — детерминированный fold ledger;
   root hash воспроизводим; перестройка эквивалентна.

## A.3 Независимые оси (полки) — ядро анти-дрифта

| Ось | Отвечает | Никогда не отвечает |
|---|---|---|
| ComponentIdentity (opaque `ComponentId`) | что это за кусок навсегда | номер/путь (DesignationVersion), силу |
| TextVersion (CTV) | какая формулировка между ударами | силу, применимость |
| OperativeMembership | в действующем дереве на t? | силу текстом, documentary presence |
| **DocumentaryPresence** | Tombstone / Present / Absent в документной структуре | юридическую силу |
| ForceStatus (interval set) | InForce / NotYetInForce / Suspended / Repealed / … | текст, применимость |
| TransitionConstraint | для каких старых отношений ещё старая версия | воскрешение слота |
| ReferenceMention/Binding/Semantics | кто куда отсылал, биндинг, режим | `amends`, силу цели, авторскую правку отсылки |

Неравенства (канон `prd/temporal-legal-model.md` §6, усилены критикой):

```text
текст существует        ≠  действует
принят/опубликован      ≠  вступил в силу          (vacatio: 44-ФЗ ст. 114)
действует               ≠  применим к делу         (ADR-0023)
компонент существует    ≠  входит в состав
ссылка существует       ≠  цель действует
Repealed-цель           ≠  сломанный биндинг
публикация              ≠  система знает
```

## A.4 Идентичность — три этажа

| Уровень | Идентичность | Пример |
|---|---|---|
| акт | Work = номер+дата+орган (ADR-0016) | 44-ФЗ от 05.04.2013 |
| нумерованный компонент | opaque `ComponentId`; path/label/eId/wId = **DesignationVersion** | «статья 31», её путь, AKN wId |
| адресуемый ненумерованный абзац | `AddressableTextUnit` с continuity через `IdentityContinuityDecision` (SameComponent/SplitFrom/MergedFrom/ReplacedByNewIdentity/IdentityUncertain) | «абзац первый п. 2» |
| слово/фраза | version-local `TextAnchor` (token span + quoted_hash) | «исключить слова …» |

AKN wId/eId, ELI URI — compatibility projections (D046), не внутренние id.

## A.5 Семя и сила — главный выученный урок

44-ФЗ: принятие 05.04.2013 → публикация 08.04.2013 → основное вступление
**01.01.2014** (ст. 114, с исключениями). 188-ФЗ меняет текст **в vacatio**
(июль 2013). Следовательно:

```text
июль 2013:  TextVersion = T31₁ (уже изменённая)
            ForceStatus = NotYetInForce (44-ФЗ ещё не действует основно)
```

Семя — это **четыре разных события**: AdoptionEvent (создал текст) /
OfficialPublicationEvent (опубликовал authoritative expression) /
EntryIntoForceEvent(s) (поэлементный commence) / ApplicabilityConstraint
(не в этом контуре — ADR-0023). Default семени: `NotYetInForce` или
`Unknown`, **никогда** автоматическое `InForce`.

## A.6 Порядок — causal DAG, не очередь

Один изменяющий ФЗ = `AmendmentInstrument`, содержит `AmendingProvision`-ы
(слоты поправки), каждый авторизует `MicroOperation`-ы, каждая порождает
типизированные `LegalEffect`-ы (Text/Membership/Designation/Force/Reference/
Transition) **без скрытых side effects**. Эффект несёт `EffectSelector`
(At / AfterPublication / OnEvent / OnCondition / ForRelationsAfter /
RetroactiveTo / Unknown). Зависимости: depends_on, targets_base_version,
supersedes, cancels, modifies_pending_effect. Линейный порядок — только
доказанная проекция DAG; некоммутируемые недоопределённые эффекты →
`OrderingConflict`, не порядок по номеру ФЗ.

## A.7 Repeal — четыре оси, не detach

```text
ст. 59 после 476-ФЗ:
  ForceStatus         = Repealed
  OperativeMembership = Absent
  DocumentaryPresence = Tombstone (номер + «утратила сила» в сводке)
  TextAvailability    = HistoricalOnly (последний CTV для цитаты)
```

Каскад детей — выводимый `RepealScope(parent, descendants=true)`, не
физическое удаление детских id.

## A.8 Ссылки — Mention / Binding / Semantics

- `ReferenceMention` — span + буквальная формулировка в конкретном CTV.
- `ReferenceBinding` — кандидат/подтверждённый target + evidence + статус.
  Успешный биндинг **не уничтожается** Repealed-целью.
- `ReferenceSemantics` — kind + temporal binding mode:
  IdentityAmbulatory / DesignationLiteral / FixedExpression / AsOfSpecifiedDate /
  EventRelative / **Unclassified (default)**.
- Удар по источнику → пересматривает occurrence; удар по цели → меняет
  только checkout цели. `cites` ⊥ `amends` ⊥ сила.

# Часть B. Процессы и данные (конвейер)

## B.1 Общий поток

```text
[0] Профиль акта (YAML)
      ↓ параметры станка (mint_levels, лексика ops, типичные часы)
[1] Инжест официальных артефактов (C0-семя, C1-поправки, сводки-оракулы)
      ↓ SourceArtifact + artifact_hash
[2] Парсинг → кандидаты (mention, структурные кандидаты)
      ↓ ReferenceMention, ReferenceBinding(candidates, Proposed)
[3] Юридический разбор формулы → микрокоманды
      ↓ MicroOperation + preconditions + EffectSelector
[4] Ledger: append-only утверждения о событиях
      ↓ LegalEventAssertion {evidence_span, recorded_at, asserted_by, status}
[5] Deterministic amendment compiler: fold по causal base
      ↓ LegalEffect[]: Text / Membership / Designation / Force / Reference / Transition
[6] Проекции: lossless CST (green) + semantic AST (red) + temporal graph + reference index
      ↓ Merkle root; structural sharing; exact-text reconstruction
[7] Экзамен оракулом: fold(events,t) ≈ snapshot(oracle@t)
      ↓ scoped discrepancy report (разъезд = дыра разбора, не «затереть фото»)
[8] Checkout(work, legal_as_of, known_as_of, view_mode, scope)
      ↓ view: Promulgated / Operative / HistoricalCitation / Reference / (CaseApplicable — позже)
```

## B.2 Вход/выход каждого этапа

| Этап | Вход | Выход | Запрет |
|---|---|---|---|
| 0 профиль | YAML | станок | хардкод 44-ФЗ/94 статей |
| 1 инжест | официальные файлы | SourceArtifact + hash | сводка как parent истории |
| 2 парсинг | артефакт | mention/структурные кандидаты `[Proposed]` | кандидат = факт |
| 3 разбор | C1-текст | микрокоманды + preconditions | склеить изложить/repeal/suspend/особенности; LLM-деонтика |
| 4 ledger | микрокоманды + evidence | assertions (append-only) | rewrite-in-place; latest-wins |
| 5 compiler | assertions (accepted) | typed effects | скрытые side effects; fuzzy patch «к похожей статье» |
| 6 проекции | effects | CST/AST/graph + root hash | normalized hash как exact-text proof |
| 7 экзамен | проекция vs оракул | discrepancy report | oracle-tree-back как канон |
| 8 checkout | (work, legal_as_of, known_as_of, view_mode) | view + coverage + applied/excluded effects + conflicts + unknowns + provenance + root_hash | latest; события с effect > legal_as_of; None вместо typed non-success |

## B.3 Snapshot формально

```text
Snapshot = fold(
    assertions
    where recorded_at <= known_as_of
      and status in {Validated, AuthoritativeInternal}
      and effect_selector satisfied for legal_as_of
)
```

Выход checkout несёт: legal_as_of, known_as_of, view_mode, root_hash,
coverage, applied_effects, excluded_future_effects, conflicts, unknowns,
provenance.

## B.4 Алгебра операций (закрытый реестр, P1)

```text
Text:         ReplaceText / InsertText / DeleteText / SubstituteRange / CorrectText
Structural:   Attach / Detach / Move / Renumber / Redesignate / Split / Join /
              ReplaceStructure / ReserveDesignation
Force:        Commence / Suspend / Resume / Repeal / Expire / Invalidate / Restore
Prospective:  ScheduleEffect / ModifyPendingEffect / CancelPendingEffect
Table/List:   InsertEntry / DeleteEntry / SplitEntry / MergeEntries / ReclassifyEntry
```

Каждая операция: target selector, expected base version, precondition
(old text/structure), payload, effect selector, scope, postcondition,
evidence span. Результат: `Applied | TargetNotFound | AmbiguousTarget |
PreconditionMismatch | BaseVersionMismatch | OrderingConflict | UnknownEffect |
UnsupportedOperation | IncompleteSource`.

## B.5 Учебный прогон (исправленный, с vacatio)

```text
2013-04-05  Adoption 44-ФЗ: mint слотов, T*, сила NotYetInForce/Unknown
2013-04-08  OfficialPublication (source_publication)
2013-07     188-ФЗ (после 10 дн. от публик. 188-ФЗ): T31₀→T31₁ — prospective,
            сила 31 всё ещё не основное InForce 44-ФЗ
2014-01-01  EntryIntoForce (ст. 114 ч.1): поэлементный commence (исключения позже)
2022-01-01  476-ФЗ: ст. 53–59 → Repealed + Operative absent + Tombstone +
            TextAvailability HistoricalOnly; переходные — TransitionConstraint
            («для извещений до 01.01.2022 — прежняя редакция»)
```

Checkout(2013-07-15, OperativeView) честно виден: текстов — уже T31₁,
действующих норм 44-ФЗ — по ст. 114 почти нет. Это ровно тот случай,
который сломал букварь Review 12.

# Часть C. Итоговый результат (что получаем в конце)

Не «текст закона на дату», а типизированные виды:

| View | Содержание | Потребитель |
|---|---|---|
| PromulgatedTextView | authoritative текст, принятый/опубликованный | сверка с первоисточником |
| OperativeTextView | положения в силе на legal_as_of | агент, ретривер |
| HistoricalCitationView | полный исторический текст, включая repealed + tombstone | цитата, спор, аудит |
| ReferenceView | mentions, bindings, target states | резолвер, impact-анализ |
| CaseApplicableView | позже, ADR-0023 runtime | дело заказчика |

Каждый view: с root_hash, coverage, provenance до evidence span, typed
unknowns/conflicts. Метаморфические инварианты (приёмка):

1. Повторный replay → тот же root hash.
2. Перестановка независимых событий не меняет snapshot.
3. Перестановка зависимых запрещена или OrderingConflict.
4. Будущие эффекты не влияют на historical checkout.
5. Исправление assertion не переписывает known_as_of-прошлое.
6. Изменение цели ссылки не меняет source mention.
7. Изменение source text закрывает occurrence, может сохранить continuity.
8. Каждый узел snapshot — provenance или typed Unknown.
9. Exact-text reconstruction воспроизводит официальный артефакт (через CST).
10. Никакой None не заменяет юридически значимый non-success.
