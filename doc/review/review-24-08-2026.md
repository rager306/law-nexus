# Часть II. Перепроверка

Каждый пункт: **утверждение критики** → **факт / канон** → **вердикт
перепроверки**.

## II.1. Сводка ≠ история — СОГЛАСИЕ, УЖЕ КАНОН

Критика: изменяющий акт = причина; сводка = результат; XML-diff не устанавливает
кто/формула/часы/условие/переходные/характер акта.

Канон: ADR-0017 §1c EditionOracle = checksum; Review 10 R10-01; evidence class
`legislative` > `hypothesized_from_oracle_diff` > `editorial_hint`.

**Вердикт:** accept as restatement. Не новая норма.

## II.2. CC ≠ CTV, отказ TV=Work — СОГЛАСИЕ, УЖЕ КАНОН

Критика: de Martim силён event-centric CTV; TV как новый F1 Work — LRMoo-мэппинг,
не обязателен; отказ обоснован.

Канон: ADR-0016 §6 + ADR-0017 Context (Review 4). SAT-Graph RAG
([Sage FAIA251598](https://journals.sagepub.com/doi/10.3233/FAIA251598)) —
эмпирика reusable CTV, не proof РФ.

**Вердикт:** accept. Не поднимать SAT-Graph в канон.

## II.3. Полки независимы — СОГЛАСИЕ, УЖЕ КАНОН + УТОЧНЕНИЕ

Неравенства критики совпадают с `prd/temporal-legal-model.md` §6 и Review 12 A1.
Новое имя осей для repeal (K8): `OperativeMembership` vs `DocumentaryPresence`
в Reviews 10–12 **не разделены явно** (был «состав» одним словом).

**Вердикт:** полки оставить; **добавить** documentary presence как ось
(не схлопывать с detach).

## II.4. Пакет микрокоманд, active/passive, удар по источнику ≠ удар по цели

Согласие. Уже Review 10–11. AKN active/passive:
[AKN Core Part 1 Vocabulary](https://docs.oasis-open.org/legaldocml/akn-core/v1.0/akn-core-v1.0-part1-vocabulary.html).

ThLexGraph Citation F1 0.812 vs web 0.666
([ACL 2026 industry](https://aclanthology.org/2026.acl-industry.124/)) —
другой правопорядок; аргумент **за структурный слой**, не за нашу онтологию.

**Вердикт:** accept restatement. ThLexGraph не канон.

## II.5. K2 — Lossless CST + Semantic AST — НОВОЕ, ПРИНЯТЬ КАК ПРОЕКЦИЮ

Критика: термин AST рискует выкинуть кавычки, пробелы, таблицы, примечания,
сноски, «ломаную» разметку источника. Официальный текст нельзя восстанавливать
из абстрактного дерева.

Паттерн: Roslyn red/green
([Lippert 2012](https://ericlippert.com/2012/06/08/red-green-trees);
[Roslyn Design doc](https://github.com/dotnet/roslyn/blob/main/docs/compilers/Design/Red-Green%20Trees.md)):
immutable green = full fidelity; red = semantic façade; structural sharing.

В Reviews 10–12: Manifestation = файл сводки / checksum, текст CTV = «формулировка»,
но **нет** требования lossless reconstruction artifact. ADR-0013 парсит в
структурные кандидаты; это не green tree закона как канон сечений.

Три хеша (`artifact_hash` / `lossless_root_hash` / `normalized_semantic_hash`)
согласуются с «normalized ≠ exact-text proof».

**Вердикт:** **принять как целевой слой проекции**, не как замену ledger.
Не чеканить типы в этой итерации. Не объявлять парсер HEAD lossless CST.
Имя «green/red» — техническая аналогия, как Git: не store Roslyn в продукте.

Оговорка: для *изменяющего акта* green tree пакета C1 и green tree *сечения*
44-ФЗ — разные артефакты. Склеить их в один AST — новая ошибка.

## II.6. K3 — path/wId как личность — ДЕФЕКТ БУКВАРЯ, УСИЛЕНИЕ ADR

Review 12 A1 буквально: «личность — путь/wId». Критика права: путь ломается
на move / renumber / split / join.

Канон уже слабее букваря:

- ADR-0016: Work = номер+дата+орган, не path; ELI URN — проекция.
- ADR-0017: CC = F1 abstract identity; industrial `renumber`/`move`/`split`/`merge`
  пишут membership log, не «новый CC из нового номера».
- AKN wId — соглашение обмена относительно master expression
  ([AKN Naming Convention](https://docs.oasis-open.org/legaldocml/akn-nc/v1.0/akn-nc-v1.0.html)),
  не внутренняя онтология.

Opaque `ComponentId` + `DesignationVersion` (kind, label, path, eId, wId,
intervals) + `IdentityContinuityDecision` — **уточнение**, не конфликт с
ADR-0016 Work. Conflict был бы, если бы мы сказали «Work тоже UUID без
номер+дата+орган». Нет: Work остаётся юридическим именем акта; слот внутри
Work получает непрозрачный id.

**Вердикт:** **принять**. Review 12 A1 считать ошибочно сильным. wId/eId/path
оставить compatibility + designation, не identity.

### Канон, которому букварь противоречит

- ADR-0009: `legal_act_effect` **не есть** определение `InForce` и не есть

- ADR-0018: нет статуса `InForce` по умолчанию; нет evidence → `Unknown`;

force-события — не `InForce` с даты принятия.

### Развилка: статус `Transitional`

Критика: `Transitional` не входит в силу; это применимость.

Канон ADR-0018 **включает** `Transitional` в enum NormativeState;
ADR-0021 владеет выбором версии переходных; applicability runtime — ADR-0023.

**Вердикт:** **не принимать молча.** Зафиксировать развилку F13-T:

- T1 (критика): вынуть `Transitional` из force-enum; переходные только оверлей
  ADR-0021 + case view.
- T2 (текущий ADR-0018): оставить как статусный ярлык «действует лишь через
  переходную», не ApplicabilityDecision.

Рекомендация этой перепроверки: **T1 ближе к полкам Review 10** (сила ⊥
переходные ⊥ применимость), но это **поправка ADR-0018**, не правка букваря
в одиночку. До human — не вычёркивать enum.

Прочие статусы критики (`NotYetInForce`, `Expired`, `Invalidated`):
`NotYetInForce` — **принять как дыру enum** (сейчас её нет; vacatio 44-ФЗ
это демонстрирует). `Expired`/`Invalidated` — отложить в P1 (КС ex tunc уже
оговорён в ADR-0018 §5 как typed status event).

## II.8. K5 — очередь C1 → causal DAG — ПРИНЯТЬ КАК УТОЧНЕНИЕ ЭТАПА 2

Review 12 этап 2: «упорядочить по каузальности (даты эффекта + кнопки)»,
но в букваре это всё ещё **очередь**. Review 10 уже: один C1 = сумка с
разными часами. Этого мало для:

- правки ещё не вступившего текста (188-ФЗ vs vacatio 44-ФЗ);
- акт меняет формулу ранее принятого изменяющего;
- два некоммутирующих эффекта в один день;
- retroactive; кнопка «после ПП»;
- `modifies_pending_effect`.

EffectSelector (`At` / `AfterPublication` / `OnEvent` / `OnCondition` /
`ForRelationsAfter` / `RetroactiveTo` / `Unknown`) = формализация «сумки часов
и кнопок» Review 10, не шестые часы.

`OrderingConflict` вместо произвольного порядка по номеру ФЗ = fail-closed
ADR-0015.

**Вердикт:** **принять.** Линейный порядок — только **доказанная проекция**
DAG, не канон. Не реализовывать DAG в этой итерации.

## II.10. K7 — адресуемый абзац — ПРИНЯТЬ ПРОМЕЖУТОЧНЫЙ УРОВЕНЬ

Review 10/12: ненумерованный абзац = элемент списка, не вечный CC.
Это **правильно против позиционного eId**.

Критика: абзац может быть целью позднейших поправок и ссылок → нужна
`AddressableTextUnitConcept` + `OrderedMembershipVersion`; слова/фразы —
`TextAnchor` внутри CTV.

**Вердикт:** **принять трёхуровневую шкалу идентичности.** Не поднимать
каждое слово в CC (критика это тоже запрещает). Continuity абзаца — только
через `IdentityContinuityDecision`, не автоматия similarity (тот же запрет,
что Git rename).

Это дыра TSG-013-класса, не закрытая Review 10.

## II.11. K8 — repeal ≠ один detach — ПРИНЯТЬ РАСЩЕПЛЕНИЕ ОСЕЙ

Критика: после утраты силы одновременно (1) нет эффекта, (2) текст в истории,
(3) в сводке может торчать номер и помета «утратила силу».

Review 10: detach состава + Repealed + хранить CTV. **Не** назван
documentary tombstone. Экзамен сводкой (этап 5) без placeholder провалится
на «ст. 59 утратила силу», если сечение просто выкинет узел.

`RepealScope(parent, descendants=true)` как выводимый scoped effect, не
физическое убийство детских id — согласуется с «слот детей жив».

**Вердикт:** **принять четыре оси:**

```text
ForceStatus
OperativeMembership    — в «действующем» дереве?
DocumentaryPresence    — Tombstone / Absent / Present
TextAvailability       — HistoricalOnly / Operative / Unknown
```

`detach` оставить операцией membership, не синонимом repeal.

## II.12. K9 — dynamic default — РАЗВИЛКА, РЕКОМЕНДОВАТЬ FAIL-CLOSED

Review 11 F11-A: default dynamic (как AKN Work-IRI и «русская доктрина») vs
не биндить mode. Review 12 взял dynamic в букварь.

Критика: AKN naming — не норма РФ; ambulatory по wId может «исправить»
ошибочную отсылку законодателя. Default `Unclassified`. Mention ≠ Binding ≠
Semantics. Binding успешен при Repealed-цели.

Исследования: surface mention ≠ canonical target
([Sage FAIA251601](https://journals.sagepub.com/doi/10.3233/FAIA251601));
qualified xref + inversion-проверка
([arXiv:2608.19194](https://arxiv.org/abs/2608.19194)) — препринт, паттерн
валидации полезен, не канон.

Расширенный mode (`IdentityAmbulatory` / `DesignationLiteral` /
`FixedExpression` / `AsOfSpecifiedDate` / `EventRelative` / `Unclassified`)
богаче F11-A. `EventRelative` стыкуется с переходными 476-ФЗ (извещение).

**Вердикт:** **принять разделение Mention/Binding/Semantics** и запрет
уничтожать binding из-за Repealed-цели (это уточнение F11-C).
**Default Unclassified** — рекомендация закрыть F11-A в сторону fail-closed;
не silently rewrite Review 11 без human. Волна 1 резолвера (F11-B, только
внутренние) остаётся.

Не принимать автоматический confidence LLM как binding.

## II.13. K10 — `known_as_of` — ДЫРА КОНТРАКТА REVIEW 12, ЧАСЫ УЖЕ ЕСТЬ

ADR-0009: `system_observation` отдельный; assertion immutable; derived
bitemporal views = проекции. ADR-0017 §5: не полная bitemporal БД.
Review 12 этап 6: `checkout(Work, t)` — **второй оси нет**.

Критика `checkout(legal_as_of, known_as_of, view_mode)` согласуется с часами.
Assertion ledger (`Proposed` / `Validated` / `Rejected` / `Superseded`)
согласуется с ADR-0008/0010 promotion, не с «событие = юридический факт».

Это ровно фраза критики, которую стоит взять буквально:

> Не считать snapshot commit’ом, но и не считать извлечённое событие
> непосредственным юридическим фактом.

**Вердикт:** **принять контракт checkout и assertion-обёртку.** Не объявлять
полноценную bitemporal graph DB. Property-graph bitemporal literature
([Iris/Unito](https://iris.unito.it/handle/2318/2094991)) — compatibility.

View modes (`Promulgated` / `Operative` / `HistoricalCitation` /
`Reference` / `CaseApplicable`) — принять как **выход этапа 6–7**;
`CaseApplicable` строится **позже** ADR-0023, не compiler'ом текста.

## II.14. K11 — алгебра операций — РАСШИРЕНИЕ, ЧАСТИЧНО УЖЕ В 0017

ADR-0017 industrial: `renumber` / `move` / `split` / `merge`.
Review 10 речевые акты: изложить / исключить / repeal / suspend / особенности / mv.

Критика добавляет: CorrectText, ReserveDesignation, Suspend/Resume/Expire/
Invalidate/Restore, Schedule/Modify/Cancel pending, table/list ops,
precondition `expected base version`, typed apply results
(`PreconditionMismatch`, `OrderingConflict`, …).

**Вердикт:** **принять закрытый реестр как P1 перед resolver**, не как

# 1. Что в документе сделано правильно

## 1.1. Сводная редакция обоснованно отвергнута как источник истории

Различие:

```text
изменяющий акт = причинное событие
сводная редакция = результат применения событий
```

является фундаментально правильным.

Сравнение двух XML-сводок может показать, **что изменилось**, но не устанавливает: кто юридически произвёл изменение; какая формула использована; когда именно возникает эффект; есть ли условие или переходное положение; относится ли изменение текста к вступлению в силу; была ли это поправка, коррекция, отмена или приостановление.

Поэтому snapshot diff следует использовать только для проверки, поиска пропущенных изменений и bootstrap-реконструкции, но не как authoritative commit.

## 1.2. Правильно разделены постоянный компонент и его текст

Конструкция CC + Text Versions соответствует сильной стороне diachronic-модели de Martim. Решение считать каждую Temporal Version отдельным `F1 Work` является конкретным LRMoo-мэппингом, а не обязательным внутренним устройством. Отказ от этой части при сохранении CTV и event-centric causality обоснован.

SAT-Graph RAG также использует переиспользование неизменённых компонентных версий и first-class legislative events. Опубликованная оценка преимущественно качественная и trace-based, а не benchmark юридической корректности. ([Sage Journals](https://journals.sagepub.com/doi/10.3233/FAIA251598))

## 1.3. Независимые «полки» — центральное достоинство модели

Неравенства текст≠сила≠применимость≠состав≠знание системы предотвращают типичные ошибки юридического RAG. Измерения нельзя объединять в одну `ProvisionVersion`.

## 1.4. Один изменяющий закон правильно рассматривается как пакет микрокоманд

Подход точнее модели `Act AMENDS Act`. Event-centric исследования разделяют извлечение событий, временных отношений и построение temporal KG; обзор отмечает дефицит размеченных данных для end-to-end графов.

## 1.5. Разделение active и passive provenance полезно

Akoma Ntoso также различает active и passive modifications и предусматривает repeal, substitution, insertion, replacement, renumbering, split и join. ([OASIS AKN Core Vocabulary](https://docs.oasis-open.org/legaldocml/akn-core/v1.0/akn-core-v1.0-part1-vocabulary.html))

## 1.6. Правильно разделены изменение источника и изменение цели ссылки

Hyperlink не canonical identity; mention не разрешённая ссылка; `cites` не `amends`; отсутствие цели → typed outcome.

ThLexGraph: Citation F1 0,812 против 0,666 web search и 0,685 flat-vector; hierarchy traversal в половине агентских запросов. Другой правопорядок, эмпирика за структурный слой. ([ACL Anthology](https://aclanthology.org/2026.acl-industry.124/))

# 2. Главные проблемы текущей формализации

## 2.1. Нужен не один AST, а lossless CST плюс semantic AST

Риск потерять пунктуацию, кавычки, пробелы, заголовки, нумерацию, таблицы, примечания, сноски, формулы перечней, форматирование, неоднозначную структуру источника.

Red/green architecture Roslyn: immutable green nodes, structural sharing, lazy semantic wrappers, full-fidelity. ([GitHub Roslyn](https://github.com/dotnet/roslyn/blob/main/docs/compilers/Design/Red-Green%20Trees.md))

Ввести `SourceArtifact` / `LosslessSyntaxRoot` / `SemanticAstRoot` / `NormalizationProjection` и три хеша: `artifact_hash`, `lossless_root_hash`, `normalized_semantic_hash`. Последний нельзя использовать вместо доказательства точного текста.

## 2.2. `path/wId` не должен быть внутренней идентичностью слота

Путь меняется при перемещении, перенумерации, split/join, перестройке приложения, смене типа компонента.

AKN `wId` сохраняет тождество фрагмента между Expressions, `eId` — текущую роль; сам `wId` строится относительно master expression и является соглашением обмена, не достаточной внутренней онтологией. ([OASIS AKN Naming](https://docs.oasis-open.org/legaldocml/akn-nc/v1.0/akn-nc-v1.0.html))

Канон: opaque `ComponentId`; отдельно `DesignationVersion`; для неоднозначности — `IdentityContinuityDecision` (SameComponent / SplitFrom / MergedFrom / ReplacedByNewIdentity / IdentityUncertain).

## 2.3. Семя ошибочно объединяет создание текста и вступление в силу

Этап 1: «начальные CTV; сила с даты закона»; B0: InForce с 5 апреля 2013.

44-ФЗ официально опубликован 8 апреля 2013; статья 114 исходной редакции — основное вступление 1 января 2014, с отдельными более поздними сроками. ([Pravo.gov](https://publication.pravo.gov.ru/Document/View/0001201304080023))

Закон мог быть изменён до основного вступления. Июль 2013: `TextVersion = уже изменённая T31₁`, `ForceStatus = NotYetInForce`.

Правильная схема семени: `AdoptionEvent` / `OfficialPublicationEvent` / `EntryIntoForceEvent(s)` / `ApplicabilityConstraint`. Начальное состояние не автоматически `InForce`.

Минимальная статусная модель: `NotYetInForce` / `InForce` / `Suspended` / `Repealed` / `Expired` / `Invalidated` / `Unknown`. `Transitional` сюда не входит: это характеристика применимости, не силы.

## 2.4. «Очередь C1» должна стать causal DAG

Линейная очередь недостаточна для нескольких дат в одном акте, prospective, правки недействующей редакции, изменения формулы ранее принятого изменяющего, двух актов в один день, внешнего события, обратной силы, неопределённого порядка.

`LegalEffect` имеет `EffectSelector` (At / AfterPublication / OnEvent / OnCondition / ForRelationsAfter / RetroactiveTo / Unknown). Порядок — частичный: `depends_on` / `targets_base_version` / `supersedes` / `cancels` / `modifies_pending_effect`. Некоммутирующие эффекты без доказательства порядка → `OrderingConflict`.

## 2.5. Пакет, событие и микрокоманда пока смешаны

Четыре уровня: `AmendmentInstrument` / `AmendingProvision` / `MicroOperation` / `LegalEffect`. Одна микрокоманда может породить несколько типизированных эффектов без скрытых side effects.

## 2.6. Модель ненумерованного абзаца слишком слабая

«Абзац первый» нельзя отождествлять с постоянной позицией, но вывод «нет устойчивой идентичности» создаёт проблему: абзац может изменяться, быть целью поправок и ссылок, сохранять преемственность.

Промежуточная категория: `AddressableTextUnitConcept` + `OrderedMembershipVersion`. Слова/фразы: version-local `TextAnchor`.

## 2.7. `repeal = detach` недостаточно точно

Три состояния: нет юридического эффекта; прежний текст в истории; в документной структуре может оставаться номер и помета «утратила силу».

Оси: `ForceStatus` / `OperativeMembership` / `DocumentaryPresence` / `TextAvailability`. Каскад детей — `RepealScope`, не физическое удаление идентичностей.

## 2.8. Dynamic/static недостаточно для ссылок

AKN Work- vs Expression-level — naming convention, не универсальная норма РФ. Default dynamic рискован: следование за wId может «исправить» ошибочную отсылку законодателя.

Три сущности: `ReferenceMention` / `ReferenceBinding` / `ReferenceSemantics`. Режимы: `IdentityAmbulatory` / `DesignationLiteral` / `FixedExpression` / `AsOfSpecifiedDate` / `EventRelative` / `Unclassified`. По умолчанию безопаснее `Unclassified`.

Surface mention и каноническая цель — разные задачи. ([Sage FAIA251601](https://journals.sagepub.com/doi/10.3233/FAIA251601)). Qualified cross-references: квалификация, supporting provisions, inversion-проверка; препринт. ([arXiv:2608.19194](https://arxiv.org/abs/2608.19194))

`RepealedTarget` не уничтожает успешный факт биндинга.

## 2.9. `system_observation` есть в модели, но отсутствует в контракте checkout

Нужен `checkout(work, legal_as_of, known_as_of, view_mode)`. Внутренний канон: evidence-backed assertion ledger, не «сырой юридический факт». Поздняя коррекция не переписывает прошлое знание системы. # 3. Сравнение возможных подходов

Набор сводных редакций — oracle/checksum. AST diff — inferred candidate / QA. Обычный Git — storage pattern, не домен (commits are snapshots, rename эвристичен). ([GitHub Blog](https://github.blog/open-source/git/commits-are-snapshots-not-diffs/)). Event sourcing микрокоманд — каноническая история. AKN/ELI/LRMoo/LegalRuleML — compatibility. Hybrid ledger + persistent CST/AST + graph — **целевой подход**.

Полезные свойства Git сохранить: content-addressed TextVersion, Merkle root checkout, structural sharing, tamper-evident hashes. Но `hash ≠ ComponentId`, `path ≠ ComponentId`, `similarity ≠ identity continuity`.
