## 3. Постоянные принципы исполнения (для каждой волны)

1. **FSM-дисциплина.** Процессы (и GSD-юниты, и продуктовые пайплайны)
   проектируются/описываются как FSM: явные состояния, переходы, ограничения
   (guards), критерии завершения. Канон продукта — assembly FSM
   `S_ready_bounded` (не O3, не TSG S6; D098). Новый поведенческий код получает
   FSM-описание в ADR/плане слайса до имплементации.
2. **Архитектура.** Гексагональная/луковичная (ADR-0013): зависимости
   домен←application←adapters; переиспользование существующих компонентов прежде
   нового кода; перед правкой символа — GitNexus `impact`; перед коммитом —
   `detect_changes`; вопрос «нужна ли коррекция архитектуры» решается ADR, не
   молчаливым дрейфом.
3. **TDD и тесты.** Новое/изменённое поведение — red-test первым; тесты по
   ADR-0015 и verification-matrix (overlapping contours, fail-closed путь);
   >1 адаптера → port contract в `ln-testkit`; консультант ≠ гарантик;
   `consru_export` = `[smoke]`.
4. **ADR-дисциплина.** Архитектурное решение (новая зависимость, смена
   направления, новый процесс-канон) → ADR по шаблону `doc/adr/`, до или в том
   же changeset, что и код.
5. **Без хардкода.** Настройки — в `.env` репозитория (по возможности),
   `.env.example` — зеркало; секреты только через secure_env_collect, никогда в
   коде/логах/артефактах. Дефолты в коде допустимы только как fail-closed
   значения, не как скрытая конфигурация.
6. **Анализ индексов каждую сессию.** GitNexus (repo `law-nexus`) — всегда:
   query/impact/detect_changes; свежесть индекса — проверять, после
   tracked-коммитов — `node .gitnexus/run.cjs analyze --force --name law-nexus`
   (MEM1135). codebase-memory-mcp — по необходимости (semantic/vector search,
   data-flow tracing), индексация одобрена пользователем, но не как отдельное
   действие ради действия.
7. **Логи.** Анализировать логи приложения и процессов, затронутых изменением
   (governor/preflight отчёты, тестовый вывод, stderr крейтов); структурные
   ошибки — в TSG/known-defects, не в чат.
8. **Финал сессии (обязательный пакет).** Полная батарея (governor JSON-отчёт,
   preflight, pytest, `cargo fmt --all --check`, `cargo check --workspace
   --offline`, ADR-conformance); sync docs + CHANGELOG; атомарный коммит
   (detect_changes перед ним); оценка «что усилить в Governor CLI / review-логике»
   по фактическим ошибкам сессии (D272: exercise-not-expand — новый check_id
   только если существующие не могут нести правило); проверка логов GSD-сессии и
   приложения; простой итоговый отчёт: сделано / проверено / осталось /
   приоритетный следующий шаг.
