## Build profile — measured, not argued

The dev-profile change was driven by measurement and one of my earlier
comments was wrong. A 4-combination matrix on a real `ln-status` test binary:

| `debug` | `strip` | size |
|---|---|---|
| `0` | `debuginfo` | 1.2 MB |
| `line-tables-only` | `debuginfo` | 1.2 MB |
| `0` | none | 7.0 MB |
| `line-tables-only` | none | 7.0 MB |

Size is moved by **strip**, not by `debug`. `debug = false` saved 200 bytes and
lost backtrace frame file:line — a bad trade, so `line-tables-only` stays.
`incremental = false` is the real win in this workspace: `target/debug/
incremental` held 1.7 GB across 513 test targets (cargo's own directory, not
the compiler cache), now 4 KB; rebuild cost 2.4 s. `target/` went 17 GB to
3.1 GB overall this session.

Two knobs for triage, both verified:
`CARGO_PROFILE_DEV_STRIP=false uv run cargo test ...` restores backtrace
frames for one run, and `cargo test --profile debugging` is a declared profile
(inherits dev, `strip = false`, separate fingerprint) that does not thrash dev
artifacts.

## Environment rule I got wrong once

Run Python through `uv run --frozen`, as CI does
(`.github/workflows/repository-quality.yml`). `.venv/bin/python` happens to be
the same uv-managed interpreter, so results matched, but `uv run` also honours
the lock and project settings. Use `uv run --frozen pytest ...`, not a bare
`pytest` and not `python3 -m pytest`.
